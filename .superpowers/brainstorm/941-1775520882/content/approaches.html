Architecture — 3 approches

Choisir la structure du système. Ma recommandation est A.

A

Video Studio App

Recommandé — Next.js 15 App Router + Remotion Player embarqué. Interface split-pane : panneau gauche (controls/IA), panneau droit (preview live). Templates organisés par type dans /remotion/compositions. Render déclenché par Server Action. shadcn/ui + Framer Motion pour l'UI.

Pour

  • Une seule app, un seul npm run dev
  • Preview live dans le navigateur
  • DX fluide, pas de switch de port

Contre

  • Next.js + Remotion dans le même bundle = config webpack/turbopack à soigner
B

Studio + Remotion Studio parallèle

Next.js sur :3000 pour l'UI + npx remotion studio sur :3001 pour le preview. Next.js trigger les renders via API route, Remotion Studio reste pour le debug de compositions.

Pour

  • Remotion Studio officiel = meilleur DX pour écrire des compositions
  • Séparation claire UI / compositions

Contre

  • 2 serveurs à lancer
  • Expérience utilisateur final fragmentée
C

Next.js léger + Remotion CLI only

Next.js pour le dashboard et la gestion de projets vidéo (JSON configs). Pas de preview live dans le browser — on ouvre Remotion Studio à la demande. Render via npx remotion render depuis un terminal ou un bouton qui appelle un script.

Pour

  • Plus simple à configurer
  • Pas de conflit de bundler

Contre

  • Pas de preview intégré = friction élevée
  • Expérience "studio" dégradée
